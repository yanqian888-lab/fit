# 搭子主动消息系统需求文档

## 一、需求概述

在搭子tab中增加**主动消息发送功能**，由搭子主动向用户发送消息，引导用户聊天、提醒打卡、通知系统消息。主动消息使用**模板话术**，不调用AI，按策略分时段发送。

---

## 二、搭子tab功能定位

| 功能模块 | 说明 | 技术方案 |
|---------|------|---------|
| **1. 模板消息** | 搭子主动发送引导/提醒消息 | 模板库 + 定时策略，不调用AI |
| **2. 智能聊天** | 用户主动发起对话，AI回复 | 现有主Agent + helperAgent |
| **3. 系统消息** | 运营通知、活动推送等 | CMS后台发送（后续开发） |

---

## 三、模板消息发送策略

### 3.1 发送时段与场景

| 时段 | 时间范围 | 消息类型 | 触发条件 |
|------|---------|---------|---------|
| 早餐时段 | 7:30-9:00 | 早安+早餐提醒 | 该时段内用户未与搭子聊天 |
| 午餐时段 | 11:30-13:00 | 午餐询问 | 该时段内用户未与搭子聊天 |
| 晚餐时段 | 17:30-19:00 | 晚餐提醒 | 该时段内用户未与搭子聊天，且未触发智能降级 |
| 运动询问 | 19:00-20:00 | 今日运动情况 | 当天未聊过运动相关内容，且发送额度未满 |
| 冷启动唤醒 | 用户打开APP时 | 寂寞唤醒话术 | 连续5条消息用户未回复（包含模板消息） |

### 3.2 防打扰规则

1. **时段内已聊天则不发送**：若用户在早餐/午餐/晚餐时段内已与搭子有消息往来，则该时段不发送模板消息
2. **运动话题已聊则不发送**：若当天用户已发送过包含"运动、步数、跑步、走路、健身、锻炼"等关键词的消息，当天不再发送运动询问
3. **连续未回复冷却**：若用户连续5条消息未回复（包含模板消息），暂停发送模板消息，直到用户主动回复或下次打开APP时触发唤醒话术
4. **每日上限**：每天最多发送3条模板消息（早/午/晚/运动合计），运动消息占用额度
5. **智能降级**：若早午餐消息发送后用户均未回复，则不发送晚餐时段消息，改为晚上发送运动消息（若当天未聊过运动）

### 3.3 发送逻辑流程

```
早餐时段（7:30-9:00）
  └─ 用户该时段未聊天？
      ├─ 是 → 发送早餐模板，计数+1
      └─ 否 → 跳过

午餐时段（11:30-13:00）
  └─ 用户该时段未聊天？
      ├─ 是 → 发送午餐模板，计数+1
      └─ 否 → 跳过

晚餐时段（17:30-19:00）
  └─ 当天已发消息≥2条且用户均未回复？
      ├─ 是 → 跳过晚餐，改为晚上发运动消息
      └─ 否 → 继续检查
          └─ 用户该时段未聊天？
              ├─ 是 → 发送晚餐模板，计数+1
              └─ 否 → 跳过

运动时段（19:00-20:00）
  └─ 当天已聊过运动？
      ├─ 是 → 跳过
      └─ 否 → 继续检查
          └─ 当天已发消息<3条？
              ├─ 是 → 发送运动模板，计数+1
              └─ 否 → 跳过（已达上限）
```

## 四、话术模板库

### 4.1 模板设计原则

- 每种模式（温柔/严格/损友）独立话术
- 每个场景至少5条话术，每天随机选取
- 话术长度控制在1-2句话，不超过30字
- 口语化、有温度，符合搭子人设
- 可插入用户昵称、今日日期等变量

## 五、系统消息（CMS后台）

### 5.1 消息类型

| 类型 | 示例 | 优先级 |

**已确认**：CMS后台不支持撤回/编辑功能

## 六、技术实现方案

### 6.1 数据库表设计

```sql
-- 模板消息配置表（CMS后台配置，预留）
CREATE TABLE template_configs (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  template_type VARCHAR(32) NOT NULL, -- breakfast/lunch/dinner/exercise/wakeup
  mode VARCHAR(16) NOT NULL, -- gentle/strict/tease
  content TEXT NOT NULL,
  sort_order INTEGER DEFAULT 0,
  is_enabled TINYINT DEFAULT 1,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- 模板消息发送记录
CREATE TABLE template_messages (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id INTEGER NOT NULL,
  template_type VARCHAR(32) NOT NULL, -- breakfast/lunch/dinner/exercise/wakeup
  content TEXT NOT NULL,
  sent_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  is_read TINYINT DEFAULT 0,
  FOREIGN KEY (user_id) REFERENCES users(id)
);

-- 用户消息互动统计（用于判断是否需要发送模板消息）
CREATE TABLE user_chat_stats (
  user_id INTEGER PRIMARY KEY,
  last_message_at DATETIME,
  consecutive_unread INTEGER DEFAULT 0,
  today_message_count INTEGER DEFAULT 0,
  today_exercise_mentioned TINYINT DEFAULT 0,
  last_active_date DATE,
  FOREIGN KEY (user_id) REFERENCES users(id)
);
```

### 6.2 定时任务

- 每15分钟检查一次是否需要发送模板消息
- 检查逻辑：
  1. 当前时间是否在发送时段内
  2. 该时段内用户是否已有消息往来
  3. 用户连续未回复次数是否<5（包含模板消息）
  4. 当天是否已发送过该类型消息
  5. 检查智能降级：若早午餐均未回复，跳过晚餐改发运动
  6. 随机选取一条该场景的话术发送
  7. 更新当天发送计数

### 6.3 冷启动检测

- APP启动时调用 `/api/chat/stats` 获取用户聊天统计
- 若 `consecutive_unread >= 5`，发送唤醒模板消息
- 发送后重置 `consecutive_unread = 0`

### 6.4 前端展示

- 模板消息与AI消息样式一致，用户无感知差异
- 系统消息（CMS）使用特殊样式（如左侧带蓝色竖线）
- 消息气泡增加时间分隔线（如"今天早上"、"昨天"）
